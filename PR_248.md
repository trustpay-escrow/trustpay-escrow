## Summary

Adds a client-side **Liquidity Depth Optimizer** shown in the create-project form for escrows above 10,000 units. It visualizes constant-product AMM reserves for the funding path, estimates price impact (depth + pool fee), warns when slippage exceeds 1.0%, recommends multi-tranche deposits, and compares a direct stablecoin deposit with the DEX path swap.

## Acceptance criteria

- [x] Visualizes constant-product AMM pool reserves for the target pair (proportional reserve bars, reserve values, spot price and `k = reserveBase × reserveQuote`).
- [x] Calculates estimated price impact % and renders a `role="alert"` warning when slippage is above the configurable 1.0% threshold.
- [x] Recommends splitting large swaps into multi-tranche deposits sized so each tranche stays under the threshold; reports expected savings and caps the recommendation at 50 tranches with an explicit note.
- [x] Shows the net cost difference: direct stablecoin deposit vs. single DEX path swap vs. optimized tranches (in source-token equivalent).

## Implementation notes

- Pure AMM maths lives in `frontend/src/lib/liquidity-depth.ts` (`getAmountOut`, `calculatePriceImpactPct`, `getMaxTrancheSize`, `planTranches`, `getLiquidityQuote`); all inputs are sanitized and invalid data yields safe fallbacks.
- Tranche savings assume the pool rebalances toward the external market price between deposits; the UI states this assumption explicitly.
- `useTokenRates` simulates a read-only `get_reserves` call against a configured Soroban AMM contract via `fetchAmmPoolReserves` in `frontend/src/lib/soroban.ts`. With no contract configured, the UI renders clearly-labelled illustrative depth instead of failing.
- Pool addresses/fees are configured through `NEXT_PUBLIC_<PAIR>_POOL_ADDRESS` variables documented in `.env.example` and README.
